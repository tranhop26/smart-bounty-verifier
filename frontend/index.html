Receipt-first verification

Proof before polish.

This interface is built to make one thing obvious: a bounty only becomes real when the contract state, wallet-signed transaction, and receipt-backed outcome all line up. No placeholder dashboards, no invented verifier output, no silent fallback to demo mode.

Live reads `readContract()` drives state shown in the dashboard and inspect view.
Signed writes Every create, submit, and verify action goes through a wallet-backed client.
Receipt discipline The UI waits for a real receipt before it calls anything successful.

What Counts As Real Here

Chain state Dashboard and inspect data come from the deployed contract, not static JSON bundled in the page.
Wallet authority Write actions require an actual browser wallet and network switch through GenLayerJS.
Verifier honesty If evidence fetch fails, the contract fails closed instead of claiming a pass from incomplete data.

How this flow works

Reads use GenLayerJS readContract(). Writes use a wallet-backed GenLayerJS client, call connect() for the selected network, send writeContract(), then wait for a receipt before showing success.

Dashboard

Dashboard data comes from live contract reads. If reads fail, the UI shows an error instead of substituting fake data.

Interaction Model

The dApp follows a narrow contract discipline: read current state, send one explicit write, wait for the receipt, then read state again. That pattern keeps the UI aligned with what the chain actually accepted.

Operator Checklist

  • Choose the right network.
  • Target the exact deployed contract.
  • Connect reads before trusting the dashboard.
  • Connect wallet before write actions.
